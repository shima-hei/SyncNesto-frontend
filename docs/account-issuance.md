# 承認制の利用開始

申し込みはアプリ外で受け付け、運営者が `/system/tenants` から組織・初期Ownerを発行する。公開登録・組織の自己作成は提供しない。

新しいOwnerには7日間有効の初回パスワードとログイン先を案内メールで送る。登録済みメールの場合は既存Identityを使い、本人のパスワード・氏名・System Roleを変更しない。発行後の組織管理はOwnerに委ねる。

メール送信失敗でも発行結果を保持し、同じ組織を二重作成しない。組織一覧の「案内メール」から有効なOwnerのメール完全一致で再送できる。初回設定前は新しいパスワードを発行し、古いパスワード・全セッション・確認リンクを無効にする。本人設定済みなら案内だけを送る。

初回ログインの `password_change_required` に応じて `/initial-password` へ遷移する。保護された画面のServer Guard・クライアントAPI・AuthProviderも初回設定を確認する。API側の拒否が最終境界であり、画面の非表示だけには依存しない。

本人は初回パスワードと新しいパスワード（12〜128文字）、確認入力を送信する。成功時は初回パスワード・全セッション・本人確認リンクを無効にし、新しいパスワードで再ログインする。期限切れ・紛失の場合は既存の `/forgot-password` から登録メールで再設定できる。

既存ユーザーには初回設定を要求しない。バックエンドの `e39b52d8c013` migrationが公開前に必要。送信元・SMTP設定・FrontendのURLはBackendの環境変数で管理し、Frontendへ資格情報を公開しない。
