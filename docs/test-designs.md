# テスト設計・テストケース

## 利用の流れ

参加プロジェクトの「テスト設計書」で設計書を作成する。

1. 「テスト項目」に対象画面・機能、観点、内容、前提、テストデータ、手順、期待結果、備考を入力する。通常の項目行や明示的な区切り行を途中に挿入できる。
2. 項目の「パターン」セルの▼から既存表を選択、または「＋ 新しいパターン表を作成」を選ぶ。不要な項目は「なし」のままでよい。「現在のパターン表を開く」でその表を編集できる。
3. 「パターン管理」は用途ごとの独立した表を一覧にする。表名、因子数、有効な組み合わせ数、利用項目と件数を確認できる。項目IDから元の項目へ移動できる。
4. 表の中では縦に因子・水準・期待値、横に組み合わせを配置する。因子の水準は○で1つ、期待値は●で複数選択できる。期待値領域を太線で区切る。組み合わせの自動名はP001形式。名称は直接編集でき、組み合わせは「＋」で追加、選択列を複製・削除できる。パターン管理一覧からも表を削除できる。
5. 設計を保存すると、ケースが自動で生成・更新される。
6. ケース詳細で個別の結果と備考を保存する。

「テストケース」メニューでは最初に設計書を選び、その設計書のケースを参照・実行する。

パターン表なしの項目は1ケース、表ありの項目は有効な組み合わせ数だけ展開する。空の表や有効な組み合わせがない表は0ケースとなる。設計画面の「パターン展開後」で保存前から総件数を確認でき、設計書一覧にも保存済みの総件数を表示する。項目別ケース数列は表示しない。項目IDは通常行の表示順にT001、T002…と自動採番し、挿入・削除後も区切り行を除いて振り直す。ID列への入力や貼り付けは無視する。直上と同じ非空値はグレー表示にし、セル結合による編集制約は作らない。

項目列はID、対象画面・機能、観点、内容、前提条件、手順、入力値・テストデータ、期待結果、パターン、備考の順。改行・折り返しに応じて行高を自動拡張する。手動の行高は最小高さとして扱う。

ケース一覧には項目番号と対象画面・機能を含む設計情報、表名・組み合わせID、各因子と水準、複数期待値を表示する。状態は既存の未実行・成功・失敗・保留から直接変更できる。状態のみの変更でも既存の実行結果と備考を保持する。「結果あり」「備考あり」は詳細ボタンの下に表示する。詳細では結果・備考を編集する。設計情報は設計書の保存時に同期し、変更の影響を表示する。

エビデンス追加時はケースUUIDを参照する独立したEvidenceエンティティを設ける。添付UIは今回追加しない。実行情報の表示は詳細へ、存在表示は詳細ボタン周辺へ追加することで、設計データや一覧列を増やさず拡張できる。

## 表の操作

セル選択中から同一のtextareaを入力先として保持し、直接入力はkeydownの文字を転記せずブラウザのinput/compositionで受け取る。composition中はEnter・Space・Escape・矢印等をセル操作へ渡さない。F2・ダブルクリックだけは既存値を編集バッファに読み込み、通常の直接入力は既存値を置き換える。

ケース一覧は項目番号、対象画面・機能、観点、内容、前提条件、手順、入力値、パターン、期待値、状態の順。対象画面・機能で絞り込める。UUIDは表示しない。実行状態は淡い行背景と状態選択欄の文字で区別し、設計変更は独立した「⚠ 影響あり」ボタンで示す。ボタンから開く詳細で変更・削除の状況を確認できる。

| 操作 | 方法 |
| --- | --- |
| セル選択 | クリック |
| 範囲選択 | ドラッグ、Shift+クリック、Shift+矢印 |
| 行・列選択 | 行番号、列見出しをクリック |
| 全選択 | 表内でCtrl/⌘+A |
| 編集 | 文字入力、F2、ダブルクリック |
| 編集取消 | Esc |
| 移動 | 矢印、Enter（下）、Shift+Enter（上）、Tab（右）、Shift+Tab（左） |
| セル内改行 | 編集中にAlt+Enter |
| コピー・カット・貼り付け | Ctrl/⌘+C、X、V。矩形範囲、TSV、HTML書式に対応 |
| 元に戻す・やり直す | ツールボタン、表内でCtrl/⌘+Z、Shift+Z、Ctrl/⌘+Y |
| 保存 | 保存ボタン、Ctrl/⌘+S |
| 行の追加・削除 | 項目表の末尾空行へ入力すると自動作成。選択行の上に通常行・区切り行を挿入できる。貼り付け中の新規空行は除外。選択行削除はツールボタン |
| 任意列の追加・削除 | 項目表のツールボタン。固定列は保持 |
| 列幅・行高 | 見出し境界のドラッグ、ツール欄の数値入力 |
| 書式 | 選択範囲に太字、左・中央・右配置、背景色、文字色 |

セル編集中の矢印はカーソルを移動する。確定後の矢印はセルを移動する。表の先頭でShift+Tab、末尾でTabを押すと表外へ移動できる。行・列・書式の変更もUndo対象で、保存すると履歴を区切る。履歴は直近30操作。

貼り付け先の列不足や行上限超過は全体を拒否する。TSVの改行・引用符に対応する。HTML貼り付けは本文と許可された書式だけを取り出し、HTML自体は画面に挿入しない。セル結合、数式の計算、Excelファイルのインポートは対象外。

## 保存とデータ保護

正式保存はバックエンドの構造化エンティティへ行う。セル位置やHTMLを業務データとして保存しない。書式・寸法は独立したlayoutデータで管理する。

未保存の変更がある画面離脱では確認する。確定した編集内容はユーザー・プロジェクト・設計書単位のIndexedDBへ退避し、再読み込み後に明示的に復元できる（復元候補は7日以内）。ブラウザ保存不可時は警告を出す。正式保存成功時にブラウザ下書きを削除する。「編集内容を退避」ではJSONをダウンロードできる。

保存競合はモーダルで通知し、入力を保持する。編集内容を退避し、最新データを読み込んでから再適用する。古い下書きも元versionを保持し、他の人の変更を自動上書きしない。

項目・因子・水準・パターン・関連の削除は確認付きで、正式保存前ならUndoできる。ケース同期では設計情報のみ更新し、実行状態・結果・備考は保持する。削除・無効化された関連のケースも結果を保持し、生成元が使えないことを表示する。

## 性能と責務

項目・組み合わせは設計全体で最大10,000件、パターン表は1,000件、展開対象ケースは20,000件。表は見える範囲の行・組み合わせ列をDOMに描画し、セル内編集は入力確定時に設計へ反映する。ケース一覧は50件ずつ表示する。設計APIは全体保存方式。

- `components/pages`: 一覧、設計編集の画面構成。
- `components/tables/design-grid.tsx`: 表選択・キーボード・寸法・仮想表示。
- `components/sections/cases-section.tsx`: ケース一覧と個別結果。
- `lib/sheets.ts`: 各表と構造化エンティティ間の変換、編集整合性。
- `lib/design.ts`: ID、組み合わせ生成、削除時の関連整理。
- `lib/clipboard.ts`: TSV・HTMLクリップボードの変換。
- `lib/draft.ts`: ブラウザ退避。正式保存の代替にはしない。
- `hooks/use-design-editor.ts`: Undo/Redo、保存、下書き、競合。
- `lib/api/generated/test-designs`: OpenAPIからOrvalで生成。

権限は既存のtest_plan/test_case permissionを利用する。memberは設計編集・結果記録、project_admin/system_adminは設計書削除も可能。ケース生成は設計保存時に自動で行う。

API契約・データモデルの詳細はbackendの`docs/frontend-test-design-api.md`を参照。

## 検証

```bash
node --test tests/test-designs.test.mjs
npm run format:check
npm run typecheck
npm run lint
npm run build
```

NodeのテストではTSVの往復、HTMLエスケープ、組み合わせ生成の冪等性、書式付き一括編集、水準所属、多対多の削除整理を検証する。ブラウザでは編集・保存・書式付き貼り付け・Undo/Redo・ケース生成・結果保存・復元を確認する。

## マトリクスへの変更方針

PatternTableを独立エンティティとして追加し、TestItemは任意のpattern_table_idを持つ。Factor・TestPattern（組み合わせ）・ExpectedValueはtable_idで所属を分離する。`lib/pattern-tables.ts`が表単位の編集とケース数算出、`lib/matrix.ts`が表への変換を担当する。旧TestItemPatternは互換用途のみで、新しいUIは個別組み合わせへの紐付けを作らない。

既存データはmigrationで「既存パターン表」へ移す。用途を自動推測して分割はしない。生成済みケースはID・結果を保持し、表や関連の変更後は過去の結果として参照できる。表を解除して再生成すると単独ケースを追加し、元の展開ケースを自動削除しない。

末尾空行はDesignGrid内の表示専用行であり、API送信データには含めない。一方、明示的な区切り行は`TestItem.is_spacer`として保存するが、項目数・ケース数には含めない。入力確定時にTestItemを作成する。表編集、クリップボード、Undo/Redoは項目表とマトリクスで共用する。マトリクスへ複数の○を同じ因子・パターンに貼り付けた場合、後の行の選択を採用する。
