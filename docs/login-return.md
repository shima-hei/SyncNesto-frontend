# ログイン後の元画面への復帰

認証切れで通常の画面リンクを開いた場合、Proxyは実リクエストのpath/queryを信頼ヘッダーへ上書きし、Server Guardから`next`へ渡す。ログイン、MFA、初期パスワード変更まで同じ戻り先を保持する。クライアントで検知した失効は現在のpath/query/hashを保持する。

HTTPに送られないfragmentは、ブラウザがログイン画面へ引き継いだ場合に通常画面の戻り先へ加える。既存のMCP同意・招待・共有の厳密な許可形式は維持し、外部URL、API、認証画面、encoded traversalや制御文字は戻り先へ許可しない。ログイン時のreason通知を消す操作でnextを消さない。

Cookie/CSRF/MFA/業務権限は変更しない。明示ログアウトやデモ終了は既存の遷移先を使う。追加認証完了前に業務キャッシュや本人情報を復元しない。

代表検証: Server Guardとクライアント失効、ログイン→MFA→元のTask URL、初期PW、query/hash、外部/認証ループ/偽装ヘッダー、MCP/招待/共有、ログアウト/デモの分離。実画面は専用LOCALデータだけを使う。
