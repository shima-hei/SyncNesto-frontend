# システム管理と組織業務の切り替え

通常ログイン・MFA完了後の既定の遷移先は `/entry`。最新の本人情報でsystem_adminは `/system`、それ以外は従来の `/` へ進む。
初回パスワード設定とMCP同意画面への明示した戻り先を優先する。業務画面 `/` 自体は管理ホームへ転送しない。

system_adminにはサイドバー上部に「組織の業務画面へ」または「システム管理へ」を表示する。
切り替え時はDocumentごと遷移し、既存の未保存確認と組織選択のsessionStorage復元を使う。保存通信中は切り替えを無効にする。
権限を変更したり運営者を組織へ自動所属させたりしない。組織未所属の場合もシステム管理は利用できる。

システム管理のShellはTenantProviderから独立し、組織選択・組織の通知・業務メニューを表示しない。
管理APIのキャッシュキーには本人IDと通常/デモの識別を含める。組織業務では既存のTenantProviderと組織単位キャッシュを維持する。

| 画面                         | 内容                                                                        |
| ---------------------------- | --------------------------------------------------------------------------- |
| `/system`                    | 組織数・Identity数・有効な所属なしの人数、管理の入口                        |
| `/system/tenants`            | 組織検索/状態/ページ分割、Owner・所属人数、既存の発行と案内再送             |
| `/system/tenants/[tenantId]` | 組織メタデータと所属ユーザー一覧。組織内の状態とアカウント全体の状態を区別  |
| `/system/users`              | 従来のIdentity一覧に有効な組織所属なしの絞り込みを追加                      |
| `/system/users/[userId]`     | 全所属組織、共通アカウント設定、既存のMFA復旧。組織詳細への戻り先を引き継ぐ |

管理対象APIはBackendの `docs/frontend-system-management-api.md` を参照。
組織詳細の閲覧では対象組織を業務用の選択組織へ設定しない。業務へのアクセスは従来の組織・Project権限を要求する。
所属停止・アカウント停止・組織停止を別々に表示し、共通アカウント変更が全組織に影響することをユーザー詳細で説明する。
システム設定・機能許可・全体監査ログ画面は今回追加しない。

Backend先行、Frontend後行で配置する。DB migrationは不要。既存の発行・再送・ユーザー編集APIを変更しない。
