# 要件の最終判断

確認表の「5. 最終判断」から、保存版・採用根拠・指定担当を固定して依頼する。新画面は `/projects/joined/{projectId}/requirement-verdicts/{requestId}`。確認表の同じ行と元の要件一覧へ戻れる。

- テストケースの確認OK、証拠の保全完了、要件全体の合格を区別する。
- 指定本人が根拠を確認し、合格・不合格・対象外と理由を確定する。自己指定を認める。
- 通常履歴・固定本文・元の実行記録は段階表示する。未解決条件、版の違い、資格失効は必要時に表示する。
- 添付は1ファイルずつ確認を進める。GET表示だけで再ダウンロードしたと扱わない。
- 後続NG・保留は、保存済みの合格を残して再判定必要にする。後続OK、取消、撤回で以前の合格へ自動復帰しない。
- 再依頼は直前依頼と実際に見直す判断を明示してつなぐ。
- 概要の「検証と最終判断」は合意とは別列。権限不足・未集計・添付未再照合を合格や0件へ補完しない。

APIと認可の正本は Backend `docs/requirement-verdicts.md`。クライアントは OpenAPI から Orval で生成する。新API経路はBFF・ブラウザともno-storeを維持する。既存正式承認、通知、テスト編集・実行保存は変更しない。

検証：Nodeテスト138件、format/typecheck/lint/build成功。隔離実APIで本人確認・20MiB添付照合・合格・NG後OKの再判定表示・明示再依頼/取消・同じ確認行/概要へ戻る操作・通信失敗/再試行・390/1440pxのLight/Darkを確認。既存の認証フローを利用し、新規依存は追加しない。
